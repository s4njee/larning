# Study Guides

This repository collects practical study guides for cloud, frontend, systems, and security topics. Each guide is written to be usable on its own, with the goal of helping you learn the subject by connecting concepts to real-world workflows and examples.

## Website

The generated self-contained website lives in `html/`, with `html/index.html` as the table of contents. GitHub Pages is deployed from that folder by `.github/workflows/pages.yml`, and the workflow rebuilds every guide before publishing so the index is not stale.

To rebuild locally:

```bash
python3 build_all_guides.py
```

### Advanced Go
This guide is a depth-first treatment of the Go runtime and high-performance Go for engineers who already write Go and want to understand what happens beneath their code. Its thesis ties it to its sibling guides: in Python you fight the interpreter and in Node you fight the event loop, but in Go — already compiled to native code — you fight the allocator and the garbage collector. It covers the runtime model (native compilation, the embedded runtime, value semantics), the GMP scheduler (goroutines, work-stealing, the netpoller, async preemption, and container-aware `GOMAXPROCS`), escape analysis and allocation (stack vs heap, `-gcflags=-m`, interface boxing — the single highest-return lever), the garbage collector (concurrent low-latency mark-sweep, `GOGC` and `GOMEMLIMIT`), data structures and memory layout (slice preallocation, `[]T` vs `[]*T`, struct field packing, `strings.Builder`, cache locality), and concurrency for performance (channels vs mutexes vs atomics, contention, `sync.Pool`, bounded `errgroup`, goroutine leaks, the race detector). ### Advanced Rust
This guide is a depth-first treatment of the Rust that senior work demands, written as the sequel to the Rust for Python Developers guide: it assumes ownership, borrowing, traits, and `Result`, and goes after async, concurrency, the type-system machinery, and `unsafe`/FFI. Its thesis is that Rust's "hard" topics — `Send`/`Sync`, `Pin`, lifetimes, and `unsafe` — are one idea in four costumes: encode the invariant in the type system so violations don't compile. It covers static vs dynamic dispatch (monomorphization vs vtables, object safety, generics vs `dyn`), advanced lifetimes (`'static`, variance, higher-ranked trait bounds, and why self-referential types are impossible in safe Rust), and smart pointers / interior mutability (`Box`/`Rc`/`Arc`, `Cell`/`RefCell`/`Mutex`/`RwLock`, and the `Rc<RefCell>` vs `Arc<Mutex>` combos). It then builds concurrency from the ground up — `Send`/`Sync` as the marker traits behind fearless concurrency, scoped threads, message passing vs shared state, and atomics with the memory-ordering model (`Relaxed`/`Acquire`/`Release`/`SeqCst`) and compare-and-swap loops — before the async core: the `Future` trait and the lazy state-machine model, `Pin`/`Unpin`, the Tokio runtime (work-stealing scheduler, `spawn`/`spawn_blocking`, the never-block-the-executor rule), and the patterns and pitfalls (`join!` vs `select!`, cancellation-by-drop and cancellation safety, `JoinSet`, streams, async traits, and the std-`Mutex`-across-`await` footgun). It finishes with `unsafe` (the five powers, the soundness contract, building safe abstractions like `split_at_mut`) and FFI (`extern "C"`, `#[repr(C)]`, the C-ABI boundary), then production concerns — zero-cost abstractions and where they leak, `thiserror` vs `anyhow`, graceful shutdown, backpressure, and `tokio-console` observability — and closes with four capstones (a Tokio chat server, a bounded job processor, a safe C wrapper, and a lock-free counter).

It then goes deep on the hard parts: message-design patterns (envelopes, pub/sub, request-response, presence, framing), scaling stateful connections with a Redis backplane and sticky sessions, production concerns (the browser auth-header problem, Cross-Site WebSocket Hijacking, backpressure, heartbeats, reverse proxies), and reliability (delivery guarantees, at-least-once with acks/dedup, state recovery, the thundering herd). It closes with an honest comparison to SSE, long-polling, WebTransport, gRPC streaming, and WebRTC — including when *not* to use WebSockets — followed by five copy-paste recipes and an end-to-end walkthrough of a scalable, authenticated chat service.
