Study Guides

This repository collects practical study guides for cloud, frontend, systems, and security topics. Each guide is written to be usable on its own, with the goal of helping you learn the subject by connecting concepts to real-world workflows and examples.

Website

The generated self-contained website lives in html/, with html/index.html as the table of contents. GitHub Pages is deployed from that folder by .github/workflows/pages.yml, and the workflow rebuilds every guide before publishing so the index is not stale.

To rebuild locally:

python3 build_all_guides.py

Advanced Go

This guide is a depth-first treatment of the Go runtime and high-performance Go for engineers who already write Go and want to understand what happens beneath their code. Its thesis ties it to its sibling guides: in Python you fight the interpreter and in Node you fight the event loop, but in Go — already compiled to native code — you fight the allocator and the garbage collector. It covers the runtime model (native compilation, the embedded runtime, value semantics), the GMP scheduler (goroutines, work-stealing, the netpoller, async preemption, and container-aware GOMAXPROCS), escape analysis and allocation (stack vs heap, -gcflags=-m, interface boxing — the single highest-return lever), the garbage collector (concurrent low-latency mark-sweep, GOGC and GOMEMLIMIT), data structures and memory layout (slice preallocation, []T vs []*T, struct field packing, strings.Builder, cache locality), and concurrency for performance (channels vs mutexes vs atomics, contention, sync.Pool, bounded errgroup, goroutine leaks, the race detector). It then covers the compiler and PGO (inlining, devirtualization, a free 2–14% from profile-guided optimization, and why cgo is slower), profiling (pprof flame graphs, b.Loop benchmarks with -benchmem, benchstat, the execution tracer), the full ladder of performance levers, and ten worked recipes — preallocation, sync.Pool, bounded fan-out, atomic counters, allocation hunting, faster JSON, buffered I/O, container runtime tuning, PGO, and sharded maps — plus a decision tree.
